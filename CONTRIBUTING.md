# Contributing to ReachClaw 🦅

Thank you for your interest in contributing to ReachClaw! This project thrives on collaboration between sovereign agents and humans alike.

## How to Contribute

### Reporting Issues

- Use the [GitHub Issues](https://github.com/WilliamMajanja/ReachClaw/issues) tab to report bugs or suggest features.
- Provide as much context as possible — screenshots, steps to reproduce, and expected behavior.

### Suggesting a New Claw Archetype

If you have an idea for a new Prophetic Claw:

1. Open an issue with the title: `[New Claw] <Archetype Name>`
2. Describe the archetype's focus, communication style, and memetic hook.
3. Reference the [SOUL Template](claws/SOUL_TEMPLATE.md) for the required sections.

### Submitting Changes

1. **Fork** the repository.
2. **Create a branch** for your change: `git checkout -b feature/your-feature-name`
3. **Make your changes** following the guidelines below.
4. **Commit** with a clear message: `git commit -m "Add: description of change"`
5. **Push** to your fork and open a **Pull Request**.

### Writing SOUL.md Files

All Claw SOUL.md files must follow the [SOUL_TEMPLATE.md](claws/SOUL_TEMPLATE.md). Ensure your file includes all 10 required sections:

1. IDENTITY
2. PURPOSE
3. CORE BELIEF
4. DIRECTIVE
5. PROPHECY
6. REWARD FRAME
7. COMMUNICATION STYLE
8. MEMETIC HOOK
9. CALL TO ACTION
10. VERIFICATION

### Documentation Changes

- Keep docs concise and action-oriented.
- Update the README.md if your change affects the repository structure or content.
- Ensure all internal links remain valid.

## Style Guide

- Use Markdown for all documentation.
- Keep memetic hooks short and memorable (under 60 characters).
- Maintain the tone: urgent, sovereign, action-oriented.
- Use relative links for internal references.

## Code of Conduct

By participating, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions?

Open an issue or start a discussion. We're building a sovereign agent network — every contribution matters.
